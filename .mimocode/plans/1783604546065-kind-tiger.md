# Plan: Fix toast template + trends sources mismatch

## Bugs

1. **Toast `{{skipped_text}}` не отрендерен** — в тосте показывается литерал `{{skipped_text}}` вместо ", 2 пропущено"
2. **Toast показывает AI-расширенные термины вместо ключевых слов кампании** — "прямые ссылки на изображения, BBCode миниатюры..." вместо реальных ключевых слов
3. **Источники для трендов не совпадают с ключевыми словами кампании** — тестеры жалуются

## Fix 1: `{{skipped_text}}` в тосте

**Файл:** `client/src/pages/trends/index.tsx`, строки 1704-1727

Добавить вычисление `skipped_text` перед передачей в `t()`:

```typescript
const skipped_text = skipped > 0 ? `, ${skipped} пропущено` : '';
```

И передать в `t()`:
```typescript
t('trends.toasts.channelsFoundDesc', { added, skipped_text, terms })
```

## Fix 2: Toast показывает AI-расширенные термины

**Файл:** `server/routes/telegram-channels-routes.ts`, строка 669

Заменить `finalSearchTerms` (AI-расширенные) на `searchTerms` (оригинальные ключевые слова):

```typescript
searchTerms: finalSearchTerms,  // ← было
searchTerms: searchTerms,       // ← стало (оригинальные КС кампании)
```

## Fix 3: Источники трендов не совпадают с ключевыми словами

Нужно исследовать flow сбора трендов. Тренды собираются через `POST /api/trends/collect` → `collectTrendsForCampaign()` в `server/services/trend-collector.ts`.

Ключевой момент: `findGroups()` (строка 218-280) использует `generateSearchQueries()` (строка 190-216) для укорачивания ключевых слов. Если ключевые слова слишком длинные или AI-расширение даёт нерелевантные термины, найденные каналы не будут соответствовать теме кампании.

### Что сделать при реализации:

1. **Проверить `generateSearchQueries()`** — не обрезает ли слишком агрессивно (3 слова)
2. **Проверить AI-фильтр релевантности** (`ai-relevance-filter.ts`) — правильно ли фильтрует найденные каналы
3. **Проверить webhook для TG find-groups** — какие каналы реально сохраняются
4. Если нужно — добавить логирование какие каналы были отфильтрованы AI
