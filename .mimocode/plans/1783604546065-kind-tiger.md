# Plan: Gate style feature to signmark@gmail.com

## Problem
Style feature ("Стиль контента" accordion) needs to be visible only for `signmark@gmail.com`. Directus JWT doesn't contain email — only `id, role, app_access, admin_access, iat, exp, iss`.

## Email Source
The Layout header already shows the email via `/api/user/profile` endpoint (`server/routes/user.ts:6-57`), which fetches from Directus using admin token. The Topbar uses this via React Query.

## Approach
Use the same `useQuery` pattern as Topbar to get the user profile (including email) in the campaigns page, then gate the feature flag on email match.

### Files to modify
1. **`client/src/pages/campaigns/[id].tsx`** — the only change needed

### Changes
1. Add `useQuery` for `/api/user/profile` (same as Topbar does):
   ```tsx
   const { data: userProfile } = useQuery<{ email: string }>({
     queryKey: ['/api/user/profile', user?.id || 'me'],
     enabled: !!user?.id,
   });
   ```
2. Replace the JWT-decoding IIFE with a simple email comparison:
   ```tsx
   const isStyleFeatureEnabled = userProfile?.email === 'signmark@gmail.com';
   ```
3. Remove the debug banner (was added for diagnosis, no longer needed)

### Why this approach
- `/api/user/profile` is already implemented and working (used by Layout/Topbar)
- No server-side changes needed
- React Query caches the result (5 min stale time in Topbar), so no extra API overhead
- Simple, single-file change

## Verification
1. `npx vite build` — must pass without errors
2. `docker compose build --no-cache smm` — rebuild container
3. Login as `signmark@gmail.com` — style accordion should appear
4. Login as any other user — style accordion should be hidden
5. Debug banner removed — clean UI

## What NOT to change
- `/api/auth/me` endpoint (already partially fixed in earlier edit, but not needed for this approach)
- No other pages affected — style accordion is only in campaigns settings
