# Исследование проекта SMM Manager и предложение по рефакторингу

## 1. Обзор архитектуры

### 1.1. Текущее состояние (Backend)
Проект представляет собой Node.js приложение на базе Express. Текущая архитектура значительно улучшена в ходе последних этапов рефакторинга.
- **Маршрутизация [ЗАВЕРШЕНО]**: Основной файл `server/routes.ts` сокращен с 16,000+ строк до 114 строк. Логика успешно вынесена в `server/routes/` и `server/api/`. Все эндпоинты теперь модульные.
- **Слой данных [ЗАВЕРШЕНО]**: Drizzle ORM полностью удален. Вся работа с данными переведена на Directus SDK и прямые HTTP-запросы к Directus API. Это упростило схему, но `server/storage.ts` всё еще остается массивным (~2,100 строк) и требует дальнейшего разделения.
- **Сервисы**: Проведена частичная унификация. Внедрена папка `server/services/social-platforms/` для разделения логики соцсетей. Однако дублирование в AI-сервисах (Gemini, Claude, Fal AI) всё еще присутствует.
- **Интеграции**: Стабилизированы интеграции с Instagram, Facebook, VK и YouTube. Внедрена система проверки прав администратора (`checkAdminRights`).

### 1.2. Текущее состояние (Frontend)
- **Технологический стек**: React, Vite, Tailwind CSS, Zustand, TanStack Query.
- **Структура**: Начат процесс группировки компонентов (`components/ui`, `components/analytics`, `components/stories`). Однако основная масса (более 100 компонентов) всё еще находится в корне `client/src/components/`.
- **Состояние**: Используется Zustand. Логика авторизации и настроек вынесена в отдельные сторы.
- **Страницы**: Проведена частичная очистка, но в `client/src/pages/test/` всё еще сохраняются диагностические инструменты.

## 2. Основные алгоритмы

### 2.1. Оркестрация AI
Система поддерживает работу с множеством моделей. Внедрен `AiService`, но логика переключения между провайдерами (fallback) требует более формализованного **Provider Pattern**.

### 2.2. Публикация в соцсети (Social Publishing)
Алгоритм стабилизирован:
1. Валидация контента через `instagram-video-validator.ts` и аналоги.
2. Загрузку в S3 (Beget/AWS) через унифицированные сервисы.
3. Вызов API через специализированные классы в `services/social-platforms/`.
4. Обработку статусов через `status-checker.ts`.

## 3. Критические проблемы и узкие места

1.  **[РЕШЕНО] Сверхмассивный routes.ts**: Основной роутер декомпозирован.
2.  **Сверхмассивный storage.ts**: God Interface `IStorage` всё еще содержит слишком много методов.
3.  **Дублирование логики AI**: Похожие методы генерации текста/изображений в разных сервисах.
4.  **Отсутствие полной типизации**: В API-ответах от Directus часто используются `any`.
5.  **Сложность развертывания**: Огромное количество вспомогательных скриптов в корне требует структурирования или выноса в `scripts/`.

---

## 4. Предложение по рефакторингу (Refactoring Proposal)

### 4.1. Реорганизация Backend (Domain-Driven approach)
1.  **[ВЫПОЛНЯЕТСЯ] Декомпозиция Routes**: Продолжить очистку `server/routes.ts` и `server/app.ts`, вынося оставшуюся логику (например, вебхуки) в отдельные модули.
2.  **Унификация Services**:
    - Внедрить **Provider Pattern** для AI. Создать `BaseAiProvider` и реализации для Gemini, OpenAI, Claude.
    - Завершить миграцию всех соцсетей на классы в `services/social-platforms/`.
3.  **Разделение Storage**:
    - Разбить `storage.ts` на мелкие репозитории: `CampaignRepository`, `ContentRepository`, `SocialAuthRepository`.

### 4.2. Реорганизация Frontend (Feature-Sliced Design Lite)
1.  **Структурирование компонентов**: Перенести бизнес-компоненты в `features/` (например, `features/content-generation`, `features/campaign-management`).
2.  **Очистка**: Удалить устаревшие тестовые страницы и перенести диагностические утилиты в отдельный скрытый раздел админки.

### 4.3. Технические улучшения
1.  **[В ПРОЦЕССЕ] Валидация данных**: Расширить использование `zod` на все POST/PATCH маршруты backend-а.
2.  **Logging**: Полностью перейти на `logger.ts` (Winston), удалив прямые вызовы `console.log`.
3.  **Error Handling**: Внедрить глобальный перехватчик ошибок для Directus API, чтобы возвращать понятные сообщения пользователю.

---

## 5. План реализации (Roadmap)

1.  **Этап 1 (Критический) [ЗАВЕРШЕНО]**: Разбиение `routes.ts`, удаление Drizzle, миграция на Directus SDK.
2.  **Этап 2 (Архитектурный) [В ПРОЦЕССЕ]**: Рефакторинг AI-провайдеров и завершение типизации API.
3.  **Этап 3 (Data Layer)**: Разделение `IStorage` на специализированные репозитории.
4.  **Этап 4 (Frontend)**: Реорганизация компонентов по FSD Lite.
5.  **Этап 5 (Оптимизация)**: Удаление мусорных файлов и скриптов из корня.
