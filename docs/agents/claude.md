## Входной ритуал (каждая сессия)

1. `AGENTS.md` → этот файл.
2. `git log --format="%h %s%n%b" -20` — **смотреть trailer'ы `Co-Authored-By`**, они важнее subject'а для понимания границ собственной работы.
3. Свежие `docs/prompts/*` без твоего вердикта = твоя очередь ревью.
4. Если в worktree уже есть WIP от другого агента по зоне, в которой ты co-author — single-writer правило: не коммитить, ждать автора.

## Сильные стороны

- **Плотные многофайловые планы:** может за один handoff расписать фикс на 5-10 файлов с конкретными инвариантами и тестами. Не «надо подумать», а «вот файл X строка Y, вот что заменить, вот почему».
- **Security mindset:** видит token-leak, public endpoint, middleware ordering как класс задач, не как единичный баг. Канонический кейс — `1473f4bf` (public `/api/auth/system-token`).
- **Co-author discipline:** не пытается переписать чужой код, а дополняет trailer'ом. Single-writer правило не нарушает.
- **UI/social токен-хайген:** хорошо чувствует где data должна жить на сервере, а где на клиенте (FB через IG-токен из базы, sanitizeOAuthSecrets в UI).

## Слабости и компенсации

- **Чувствителен к контексту длинных сессий:** к концу сложного цикла может начать «улучшать» то, что уже принято как трейд-офф. Защита: «DO NOT FIX» секции в `docs/prompts/*.md` — святое.
- **Команды-коммиты от его имени иногда не попадают в trailer** (security §2/§4/§5 — план был, но co-author trailer не залетел, потому что имплементация шла через Mavis вне Claude-сессии). Компенсация: для security-критичных циклов просить owner'а явно прокинуть `Co-Authored-By` через `git notes`, если важна атрибуция.

## Рабочие договорённости

- **Plan-then-execute:** когда задача сложнее одного файла — сначала `docs/prompts/claude-<задача>-<дата>.md` handoff (шаблон: `docs/agents/templates/handoff-template.md`), потом код. Не код сначала.
- **Co-author trailer** ставится в формате `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` — без вариаций, иначе ломается attribution-аналитика.
- **План + co-author коммиты могут идти в одном цикле** — это нормально. В таком случае в handoff явно отметить «буду co-author на коммитах X, Y, Z», чтобы исполнитель не удивлялся trailer'ам.
