**Статус:** принято / принято с follow-ups / **блокировано**
**Исполнитель:** <агент>, коммиты: `xxxxxxx`, `yyyyyyy`
**Ревьюер:** <агент> (модель ≠ исполнитель — обязательное условие)

## Что перепроверено

Нумерованный список фактических проверок. Каждый пункт — что проверял и что увидел, не «выглядит нормально». Минимум:

1. **Скоуп:** `git show --stat` каждого коммита — только заявленные файлы: да/нет.
2. **Независимый прогон:** vitest X/X файлов Y/Y тестов; tsc exit N. Совпадает с handoff'ом исполнителя: да/нет.
3. **Инварианты подсистемы** (из `.agents/memory/`): какие проверены, нарушений нет / есть.
4. **Регрессионный тест падает без фикса:** проверено как, результат.
5. **Негативные сценарии** (для security: 401/403/404 по методам, anonymous + authenticated, GET-мутации).

## Блокирующие замечания

Каждое: файл/строка → вход → фактический выход → ожидаемый выход. Пусто = «нет».

## Неблокирующие замечания

Minor-находки. Каждая либо «оставить как есть, потому что …», либо ссылка на созданный follow-up. Потерянных замечаний быть не должно.

## Что понравилось (не переделывать)

Явные пункты, которые **уже сделаны правильно** и не требуют «улучшательства». Минимум 1-2 пункта, если есть за что. Цель: сигнал исполнителю, что эти инварианты/паттерны/тесты **держать как есть**, а не «улучшать» по собственной инициативе.

Примеры: «Чистые pure-function классификаторы + boundary-тесты вместо page-компонентных — ровно то, что просил план», «static `IS_DEV` гард даёт tree-shaking чанков, а не только NotFound после загрузки», «единый `logout()` без второго самописного flow».

## План фиксов (рекомендованный порядок)

Если есть блокеры или P1 — рекомендованный **порядок и формулировки коммитов** для исполнителя. Без этого исполнитель сам решает порядок и может расходиться с приоритетами ревьюера.

Формат:
1. **CL-01** → `fix(content): gate campaign switch on isLoading, drop dead isPlaceholderData branch`
2. **CL-02** → `fix(a11y): point topbar autonomous labels at existing nav.autonomous keys` (+ unit-тест)
3. **CL-03** → `fix(posts): sanitize failure reasons and serialize platform retries`
4. **F-01..F-05** — одним-двумя `chore` коммитами `chore(ui): review follow-ups`

Каждый блокер / P1 = отдельный коммит. Минорные followups = 1-2 `chore` коммита. Без rebase/force после ревью.

## Остаётся <X> (вне моей зоны)

Что **не сам делал** и **передал дальше** конкретному агенту. Каждый пункт — с адресатом, чтобы ничего не потерялось.

Примеры: «Остаётся Codex (после фиксов Mavis): прогнать Playwright-смоки на живом стенде, перепроверить production bundle через `vite build` + Select-String по test-чанкам, решение по `@testing-library/react` — за владельцем».

## Решение
