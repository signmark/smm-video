# Автономные ИИ-агенты для ведения соцсетей

Документ фиксирует текущие наработки по автоматизации создания и публикации
контента, а также roadmap к полноценным «ИИ-SMM-агентам», которые ведут
соцсети пользователей самостоятельно (минимум вмешательства владельца).

---

## 1. Где мы сейчас (апрель 2026)

### 1.1 Автономный цикл генерации (`server/services/autonomous-ai.ts`)

Главная функция: `runAutonomousCycle(state, request)`. Запускается по
расписанию через `startAutonomousExternal(...)` (см. `server/routes/autonomous.ts`).

Что делает один цикл:

1. **Определяет подключённые платформы кампании** через
   `getCampaignConnectedPlatforms(campaignId)` — читает
   `user_campaigns.social_media_settings`, возвращает список реально
   подключённых соцсетей (TG / VK / IG / FB / YT / TT / Threads). Хардкода
   `['telegram','vk']` больше нет.
2. **Тянет аналитику** лучших постов кампании (если есть).
3. **Читает пользовательские настройки автономного режима** из
   `user_campaigns.autonomous_settings` (JSON, см. §1.3).
4. **Подсасывает топ-15 ключевых слов** кампании.
5. **Берёт 50 свежих трендов** из `campaign_trend_topics`, скорит их по
   формуле `views + reactions×5 + comments×10`, выбирает топ-5 и
   рандомно один из них (даёт разнообразие между циклами).
6. **Формирует промпт** в `theme`:
   - Заголовок тренда + текст оригинала (до 600 симв) + платформа + URL +
     метрики.
   - Инструкция: «не копируй, переработай под аудиторию».
   - Ключевые слова кампании.
   - Пользовательские блоки из `autonomous_settings` (globalPrompt /
     alwaysInclude / signature) — обёрнуты в `[USER_INSTRUCTION_START/END]`
     для защиты от prompt injection.
7. **Вызывает `createContent`** — генерирует пост, сохраняет в БД с явным
   `topic` (исправлен баг `title="undefined"`).
8. **Опционально генерит картинку** через `nano-banana-pro` с AI-промптом.
9. **Планирует публикацию** через `pickOptimalScheduleTimeMsk(...)` —
   умный выбор по часам недели + бонусы за «настроение» аудитории.

### 1.3 Настройки кампании для автономного режима

**Поле в Directus:** `user_campaigns.autonomous_settings` (JSON).

**UI:** аккордеон «Настройки автономного ассистента» на странице кампании
(`client/src/pages/campaigns/[id].tsx` → компонент
`client/src/components/AutonomousSettings.tsx`).

**Структура:**

```json
{
  "globalPrompt": "Тон, стиль, аудитория. Например: пиши экспертно но дружелюбно, аудитория — владельцы малого бизнеса в РФ.",
  "alwaysInclude": "Ссылка/CTA/контакты, которые должны органично появиться в посте. Например: https://signmark.ru — попробуй бесплатно.",
  "signature": "Дословная подпись в конце поста."
}
```

Сохраняется через `PATCH /api/campaigns/:id` (роут пропускает
произвольные поля в Directus — `server/routes/campaigns.ts:221`).
Подмешивается во все ветки промпта (тренды / аналитика / общая тема).

### 1.4 Чат-ассистент (`server/services/autonomous-ai.ts` + tools)

LLM-агент, доступный через бота и веб-чат. Умеет:

- Запускать/останавливать автономный режим.
- Читать статус, аналитику, список постов (исправлен баг с
  «✅ выполнено» вместо реальных данных — `~3070`).
- Создавать посты, публиковать, генерить картинки, читать тренды.
- Заполнять анкету бизнеса (`fillQuestionnaire`).

Инструменты определены в `TOOL_IMPLEMENTATIONS`. Модель — Gemini
(`gemini-2.5-flash` для основной работы, `pro` для сложных задач).
Ключ берётся из `.env` → `GEMINI_API_KEY` (приоритет — пользовательский
ключ, fallback — глобальный).

### 1.5 Безопасность секретов

Зачищены утечки: удалён `gemini-vertex-direct.js` со Service Account
private key, убран хардкод SOCKS5 прокси и project ID. Все ключи —
только через `.env` / Replit Secrets / `getApiKey(...)`.

## 2. Roadmap к полноценному ИИ-SMM-агенту

Цель: пользователь подключает соцсети, заполняет минимальную анкету,
и **дальше всё делает агент сам** — без расписания публикаций, без
ручного выбора тем, без модерации каждого поста.

### Этап A. Контент-стратегия как первый класс (1–2 недели)

Сейчас агент генерит «один пост из тренда». Нужно:

- **Контент-план кампании** — отдельная сущность `content_plan` в БД:
  - Соотношение типов контента (продажа / экспертиза / развлечение /
    UGC / новости) — например, 20/40/20/10/10.
  - Целевая частота по платформе (TG: 1/день, IG: 3/неделю и т.д.).
  - Темы-«столпы» (3–5 ключевых, генерятся при онбординге из анкеты).
- **Планировщик** распределяет цикл по плану: следующий пост должен
  быть «экспертным», а не очередным трендом.

**Файлы для правки:** `shared/schema.ts` (новая таблица),
`server/services/autonomous-ai.ts` (выбор темы → выбор слота из плана).

### Этап B. Многоагентная архитектура (2–3 недели)

Разбить «всё в одном» на специализированных агентов под общим
координатором:

```
┌─────────────────────────┐
│   Coordinator Agent     │  ← решает что делать сейчас
└────────┬────────────────┘
         │
   ┌─────┼──────┬──────────┬──────────┬─────────┐
   ▼     ▼      ▼          ▼          ▼         ▼
 Trend  Plan  Writer    Designer   Publisher  Analyst
 Scout  Mngr  Agent     Agent      Agent      Agent
```

- **Trend Scout** — раз в N часов сканирует источники, кладёт в
  `campaign_trend_topics` (уже частично есть).
- **Plan Manager** — следит за контент-планом, решает какой тип/тема
  нужен следующим.
- **Writer** — генерит текст с учётом `autonomous_settings`,
  ключей, тренда (текущий код).
- **Designer** — генерит картинку/видео под пост (nano-banana,
  будущий video-gen).
- **Publisher** — публикует с учётом часовых поясов и
  оптимальных слотов (есть).
- **Analyst** — раз в неделю смотрит метрики, обновляет «настроение»
  в planner'е (что зашло/не зашло).

Реализация: каждый агент — тонкий wrapper с своим system prompt и
набором tools. Координатор — Gemini с tool-calling, который видит
всех остальных как функции.

### Этап C. Самообучение от метрик (1–2 недели)

Сейчас аналитика лучших постов передаётся в промпт «как контекст».
Нужно:

- Хранить в кампании **«усвоенные паттерны»** — короткие тезисы вроде
  «лонгриды по 1500 знаков в IG дают +40% к среднему», обновляются
  Analyst'ом раз в неделю.
- Подмешивать эти паттерны в `userBlocks` автоматически (в дополнение
  к ручному `globalPrompt`).
- A/B тестирование: иногда сознательно делать пост не по паттерну,
  чтобы проверить.

### Этап D. Адаптация под платформу (1 неделя)

Сейчас один и тот же текст идёт во все соцсети. Нужно:

- В Writer'е генерить **варианты под каждую платформу**:
  - TG/VK: лонгрид с эмодзи и абзацами.
  - IG: короткий хук + хештеги, упор на визуал.
  - YouTube Shorts/TT: сценарий 15–30 сек.
- Уже есть `SocialContentAdaptationDialog.tsx` на фронте — нужно
  встроить в автономный цикл.

### Этап E. Reactive-режим (2 недели)

Агент не только постит, но и **реагирует**:

- Отвечает на комментарии (TG/VK API уже умеют читать).
- Отвечает в личку по бизнес-сценарию (FAQ из анкеты).
- Эскалирует владельцу через бота, если вопрос не подходит под
  скрипт (например, скидка/жалоба).

### Этап F. Self-service onboarding (1 неделя)

Сейчас юзеру надо: создать кампанию → подключить соцсети →
заполнить анкету → настроить автономный режим → запустить.

Должно быть: **«Введи URL твоего сайта → агент сам всё настраивает»:**

- Парсит сайт → генерит анкету.
- Парсит существующие посты в подключённых соцсетях → определяет
  тон.
- Предлагает контент-план → юзер апрувит одной кнопкой.
- Запускает себя.

Часть уже есть (`suggest-sources` в `telegram-channels-routes.ts`).

## 3. Технические долги, которые мешают

1. **`createContent` имеет жёсткие formattingRules**, которые могут
   конфликтовать с пользовательской `signature` — нужно встроить
   userBlocks внутрь `enrichedPrompt`, а не клеить снаружи.
2. **Нет очереди задач** — все циклы крутятся через `setTimeout`. При
   падении сервера всё теряется. Нужен BullMQ или хотя бы persistent
   таблица `agent_jobs`.
3. **Один Gemini-ключ на всех** — при росте упрёмся в rate limit.
   Нужна пер-юзерная ротация ключей (частично есть, нужно довести).
4. **Тренды собираются не из всех источников** — RSS / Reddit / X
   пока не подключены, только Telegram-каналы и VK.
5. **Нет гварда «не публикуй фигню»** — если LLM выдала пустоту или
   токсичный текст, оно уйдёт в соцсеть. Нужен модерационный slim-агент
   перед Publisher.

## 5. Принципы, которых придерживаемся

- **Никаких хардкодов креденшелов** — всё через `.env` / Secrets.
- **Никаких silent fallbacks** на «другой ключ» / «другого провайдера»
  без явного разрешения юзера.
- **Промпт-инъекции изолируем** через `[USER_INSTRUCTION_START/END]`.
- **Деплой:** `cd ~ && docker compose up -d --build` (без отдельного
  `npm run build`).
- **Поля Directus добавляются вручную на dev и prod** — оба сервера
  держим в синхроне по схеме коллекций.
