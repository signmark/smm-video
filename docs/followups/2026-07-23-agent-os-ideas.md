### 🟡 Следующий цикл (low-hanging)

5. **Закрепить review-цикл в `docs/REVIEW-CYCLE.md`** (отдельный файл) — сейчас знание в `claude-ui-pretester-review-2026-07-22.md` + AGENTS.md. Когда-нибудь потеряется. Вынести в standalone-документ с примерами handoff'ов.

7. **Шаблон handoff'а исполнителя** — сейчас каждый Codex/Claude/Kimi пишет handoff в своём стиле. Стандарт = снижение цены следующего цикла.

### 🟢 Когда появится время (высокая цена)

8. **Context Engine** — `state.json` обновлять по итогам каждого цикла (commit hook? cron?). Без этого контекст стареет.
9. **Skills library** — превратить `docs/prompts/*` в skills с полями из дока секции 7.3: назначение, входы, запрещённые действия, точки подтверждения, ожидаемый результат, способ проверки, версия.
10. **Grounding-требование в handoff** — каждый значимый вывод привязан к `file:line`, лог-строке, тесту, тикету. Без этого «баг исправлен» = ложь.

### ⚠️ Не делать пока

- **Полноценный Model Router** в smm-video. Количество моделей фиксировано (Codex/Claude/Kimi/Mimo/Mavis), маршрутизация ad hoc достаточна. Когда появятся 3+ исполнителя на одну роль — вернуться к этому.
- **Локальный Model Router** — zookeeper делает это для своих пулов, smm-video может переиспользовать через HTTP-воркеры (см. zookeeper v0.5 `/orchestrate`).
- **Автоматические pre-commit hooks** — добровольное соблюдение работает. Сейчас внедрять — повышенная цена за низкий выигрыш.

## Специфично для smm-video (не из общей Agent OS)

### SMM Manager (раздел 11 дока)

Документ правильно говорит, что **сначала**:
- надёжная публикация
- понятные ошибки по каждой соцсети
- расширенное логирование VK-загрузки
- корректные ретраи
- восстановление интерфейса после ошибки

Это совпадает с приоритетами из `PRIORITIZED_IMPROVEMENT_PLAN_2026-07-23.md` (пункты 6-8: fail-closed, CI regression suite, CSP) — security-периметр должен появиться раньше, чем новые фичи.

### Генератор коротких видео (раздел 12 дока)

Главный барьер — **удержание**, а не модель. Переориентация video-app с model-driven на hook-driven. Конкретнее:
1. Механизм удержания (любопытство / напряжение / обещание результата).
2. Сценарная структура.
3. Payoff.
4. Точки отваливания.
5. Только потом — генерация сцен.

Авторские права (раздел 12.4) — отдельный вопрос. У video-app нет policies на происхождение музыки/изображений/голосов. Для коммерческого применения — критично.

## Что НЕ применять (наблюдать)

- **Локальные coding-модели** без оборудования — не приоритет.
- **Чипы с моделями в кремнии** — не релевантно smm-video.
- **Универсальные платформы агентов** без проверенного сценария — zookeeper уже закрывает эту нишу.
- **Новые генераторы изображений/видео** без преимущества для удержания — не инвестировать без A/B на hook-driven подходе.
