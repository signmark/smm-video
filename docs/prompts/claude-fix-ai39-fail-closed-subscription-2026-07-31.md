## Задача

`server/middleware/require-active-subscription.ts` — гейт подписки — пропускал
изменяющие запросы в трёх случаях, когда подтвердить право на действие
невозможно:

1. `catch { return next() }` — любая ошибка (Directus недоступен, таймаут, 5xx)
   означала «пропустить». Осознанный fail-open компромисс, зафиксированный в
   комментарии, но он допускает бесплатное использование платных функций в
   момент недоступности Directus.
2. `if (!token) return next()` — mutating-запрос вообще без предъявленной
   личности проходил насквозь под предлогом «это вебхук».
3. Три одинаковых сравнения с `process.env.DIRECTUS_STATIC_TOKEN` подряд —
   копипаста, эквивалентная одному сравнению.

Источник: `docs/followups/2026-07-24-security-backlog.md`, §6. Jira: `AI-39`.
Baseline: `origin/main = c9e860daded0`.

## Компромиссы и отклонения

- **Кеш оставлен и остаётся смягчением.** Свежая успешная проверка (TTL 60 s)
  переживает краткий простой Directus — это сознательная уступка исходному
  аргументу за fail-open (внешний VPS с известными простоями). Жёсткость в
  том, что после TTL простой обязан давать 503, и что срок действия
  вычисляется на каждом запросе, а не берётся из решения, принятого при
  записи в кеш.
- **Кеш ошибок не заводится.** Кешировать отказ значило бы, что один сбой
  Directus закрывает пользователя на весь TTL уже после восстановления.
- **Сброс кеша наружу не экспортируется.** Тесты изолируются уникальными
  токенами: расширять production-API ради тестов не стал.
- **Внешний catch отдаёт 503, а не next().** Непредвиденный сбой самого
  гейта — тоже отказ: иначе достаточно уронить гейт, чтобы обойти проверку.
- **Порядок монтирования в `server/index.ts` не менялся** — middleware
  намеренно стоит до нескольких ранних routers.

## Известные ограничения / не сделано

- **Оба ответа 401 различимы по коду** (`SUBSCRIPTION_IDENTITY_REQUIRED` и
  `SUBSCRIPTION_SESSION_INVALID`). Клиент сейчас на эти коды не смотрит —
  отдельная работа фронта, в scope AI-39 не входила.
- **`POST /api/tiktok/webhook` в allowlist не вносился.** Дефект шире гейта
  подписки: `tiktokAuthRouter` вообще не смонтирован в `server/index.ts`
  (наружу извлечён только GET OAuth callback для раннего bypass), поэтому и
  оба webhook-handler'а, и client-вызовы `auth/start`, `accounts`,
  `sync-settings`, disconnect сейчас недостижимы; при этом POST webhook не
  проверяет подпись и echo'ит payload — открывать его allowlist'ом небезопасно.
  Заведено отдельно как **AI-49** под эпиком AI-44.
- **Живой простой Directus специально не воспроизводился** — по указанию из
  плана боевой Directus не останавливается, fail-closed доказан тестом.
- **Остальные пункты §6** закрыты частично: гейт подписки теперь
  переиспользует список `api-auth-gate.ts`, но третьего перечисления
  публичного (`registerPublicOAuthBypass`) правка не касалась.

## Доработка по приёмке Codex (2026-07-31)

Приёмка нашла воспроизводимый blocker: проверка формы стерегла только «это
объект», а контракт полей не проверялся. Три ответа объектного типа проходили
гейт насквозь — подтверждено на `a4fb2717c`, все три давали 200 с вызовом
handler'а:

| Ответ `/users/me` | Почему проходил | Стало |
|---|---|---|
| `{}` | поля нет → `?? null` → «срок не задан» → пропуск | **503** |
| `{ expire_date: 'not-a-date' }` | `new Date(мусор)` = Invalid Date, сравнение всегда false → «не истекло» | **503** |
| `{ expire_date: <past>, is_smm_admin: 'false' }` | строка `'false'` истинна, `!!` → админ, гейт снят целиком | **503** |

В прошлой передаче я написал «неожиданная форма ответа → 503». Это был
overclaim: под «формой» проверялся только тип верхнего уровня. Три случая выше
— ровно щель между заявленным и сделанным.

Что сделано: `readExpireDate` требует явного присутствия ключа `expire_date`
(значение `null` либо разбираемая дата), `readAdminFlag` признаёт админом
только настоящий `true`, а `null`/отсутствие считает обычным пользователем;
любой другой тип — расхождение контракта → 503.

**Принятый риск, который стоит знать заранее.** Строгость по `expire_date`
означает: если поле скроют правами Directus или переименуют в схеме, прод
получит 503 на все мутации, а не «все пользователи бессрочные». Это осознанно
— 503 retryable и заметен сразу, тихая бессрочность не заметна вообще, — но
радиус большой, и это свойство, а не побочный эффект.

Red-before доработки (снятие только строгого разбора):

| Что снимаем | Красных из 39 |
|---|---|
| оба guard'а (поведение до приёмки) | **9** |

| только строгий admin-флаг | **4** |

Штатные ответы специально закреплены отдельными тестами, чтобы строгость не

пропускает, `is_smm_admin: null` — обычный пользователь, а не отказ.
