# Handoff: Claude (Opus 5) — состояние «токен сохранён» в настройках Telegram — 2026-07-26

## Задача

Owner: «После первой конфигурации ТГ, если зайти опять в настройки, поле ТГ токена показывается пустым. Надо показать юзеру что настройки сохранены, а если надо изменить — показать эти настройки чтобы можно было ввести новые. Не надо вводить юзера в заблуждение.»

Поле пустое закономерно: `sanitizeOAuthSecrets` вырезает токен из всех ответов, и это правильно (контракт `.agents/memory/oauth-sanitizer-contract.md`). Проблема чисто в подаче — UI не отличает «токена нет» от «токен есть, но мы его не показываем».

## Что сделано

1. **Сервер, `sanitizeOAuthSecrets`:** вырезая непустой секрет, функция оставляет на его месте булев маркер `has<Key>` — `hasToken`, `hasAccessToken`, `hasBotToken` и т.д. Пустая строка и отсутствующий ключ маркера не дают. Маркер из входных данных игнорируется — источник истины только сам секрет.
2. **Сервер, `mergeOAuthSettings`:** маркеры выбрасываются из входящего PATCH и удаляются из результата, поэтому в базу они не попадают. Иначе сохранённый флаг со временем разошёлся бы с реальным секретом и снова начал врать.
3. **Клиент, блок Telegram:** при `hasToken` вместо пустого инпута показывается строка «Bot Token: сохранён · Хранится на сервере и в браузер не передаётся» и кнопка «🔄 Заменить токен». По кнопке разворачивается пустое поле под новый токен, рядом «Отмена» и подпись «Оставьте поле пустым, чтобы сохранить текущий токен». После успешного сохранения поле очищается и сворачивается обратно.
4. **Клиент, инструкция про @BotFather** показывается только при первой настройке или при явной замене токена.
5. **Контракт** дополнен пунктом 3a — чем маркер отличается от плейсхолдера и почему он не хранится в базе.

Поведение при отсутствии токена не меняется: блок выглядит как раньше.

## Компромиссы и отклонения

- **Сначала пробовал обойтись без изменений сервера** — определять состояние по `telegram.chatId`, как предписывает п.1 контракта. Отбросил: в `socialMediaSettingsSchema` и `token`, и `chatId` опциональны, состояние «chatId сохранён, токена нет» достижимо, и на нём UI утверждал бы «токен сохранён» там, где его нет. Для бейджа «Настроено» правило по `chatId` остаётся в силе — оно меняется только для самого поля токена.
- **Маркер — не плейсхолдер.** П.3 контракта запрещает подставлять значения в поля токенов (откат `40417eb5`). Здесь в поле не подставляется ничего: флаг живёт рядом и имеет тип boolean. Паттерн не новый — `sanitizeFacebookAccount.hasAccessToken` так работает с самого начала.
- **Изменение затрагивает security-критичный файл**, который ломали дважды. Поэтому расширение сделано аддитивно: удаление секретов не тронуто, добавлена только эмиссия булевых маркеров и их вычистка на записи.
- Отклонение от канонического цикла: правку делал Claude (по каноническому распределению исполнитель — Hermes). Сделано по прямой просьбе owner'а в сессии деплоя.

## Известные ограничения / не сделано

- Маркеры теперь эмитятся для **всех** платформ (`hasAccessToken` у YouTube, `hasAppSecret` у Instagram и т.д.), но в UI использован только `telegram.hasToken`. Остальные блоки (VK, Threads, FB, IG) уже решают ту же проблему через «спрятать настройку при подключении» и не переделывались.
