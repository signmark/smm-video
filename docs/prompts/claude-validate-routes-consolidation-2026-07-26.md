## Что сделано

1. **Дубли устранены.** `registerSocialRoutes` больше не регистрирует `telegram/vk/instagram/facebook/youtube` — они жили дубликатами роутов из `registerValidationRoutes`, которую `routes.ts` вызывает раньше. Express завершает запрос в первом совпавшем handler, поэтому версии из `social.ts` не выполнялись никогда. Единственный дом — `validation-routes.ts`. `threads` остаётся в `social.ts`: дубликата у него нет.
2. **Явная аутентификация.** Все пять выживших роутов получили `authenticateUser`.
3. **Tenant binding VK.** `campaignId` проверяется на владение **всегда**. `CampaignAccessError` → `res.status(e.status)`; 404 и на чужую, и на несуществующую кампанию.
4. **CL-01 — `authExpired` сужен до доказанного случая.** Флаг ставится только при совпадении трёх условий: (а) проверялся **сохранённый токен кампании**, а не `token` из body — источник фиксируется переменной `tokenSource`; (б) доступ к `campaignId` подтверждён; (в) VK **структурно** подтвердил постоянную auth-ошибку. Классификатор `isPermanentVkAuthFailure` работает только по `details.error.error_code`, свободный текст сообщения не используется. Отсекаются: невалидный токен из body, сеть/таймаут (`details` пустой), провал проверки группы (`details.groupError`, при этом `users.get` прошёл), временные коды VK.
5. **Threads.** `getCampaignSocialSettings(..., { user: req.user })`; проглатывающий `catch {}` заменён на обработку `CampaignAccessError`.

## Компромиссы и отклонения

- **Код 15 (Access denied) намеренно исключён** из `VK_PERMANENT_AUTH_ERROR_CODES`, хотя `publish-scheduler.isAuthError` (`server/services/publish-scheduler.ts:632`) его учитывает. Обоснование: там классификация решает «ретраить ли публикацию», цена ошибки — лишний ретрай; здесь цена ошибки — `authExpired` на исправной кампании, письмо владельцу и выпадение из refresh cron. Access denied означает отказ по конкретному объекту и смерть токена не доказывает. Взято семейство «…authorization failed»: 5, 27, 28.

- **`campaignId` авторизуется даже когда токен пришёл в теле.** Сохранено из ревизии 1, Codex с отклонением согласился (п. 8 вердикта).
