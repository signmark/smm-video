## 2. По пунктам — коммит и суть находки

Чек-листа в тикете AI-39 нет (описание — одна ссылка на §6 беклога), поэтому
разбор по требованиям §6 и плана.

- **«не пропускать mutating request без identity»**, `6f37463db`:
  `if (!token) return next()` трактовал любую mutation без токена как вебхук.
  Достаточно было не прислать `Authorization`, чтобы пройти гейт подписки
  насквозь. Теперь 401 `SUBSCRIPTION_IDENTITY_REQUIRED`, handler не вызывается.
- **«при недоступности Directus блокировать mutations»**, `6f37463db`:
  внешний `catch { return next() }` открывал платные функции ровно на время
  недоступности проверки. Теперь сеть/таймаут/429/5xx → 503
  `SUBSCRIPTION_VALIDATION_UNAVAILABLE`; 401/403 от Directus → 401
  `SUBSCRIPTION_SESSION_INVALID`. Детали upstream наружу не идут.
- **Молчаливый fail-open на форме ответа**, `6f37463db` + `81093b3d2`:
  `userData?.expire_date ?? null` означал, что ответ без объекта пользователя
  читается как «срока нет → подписка бессрочная». Теперь ответ, который нельзя
  разобрать, → 503.
- **«публичные routes и webhooks только в явном allowlist»**, `6f37463db`:
  публичные вебхуки проходили по ветке «нет токена», то есть неявно. Теперь —
  через `isPublicApiPath` из `api-auth-gate.ts`. Второй список намеренно не
  заводился: два независимых перечисления публичного разойдутся, и молча.
- **Копипаста**, `6f37463db`: три подряд идущих сравнения с
  `DIRECTUS_STATIC_TOKEN` свёрнуты в одно (были эквивалентны одному).

Не менялось: порядок монтирования в `server/index.ts`, бизнес-роуты,
публичные callback-контракты, `api-auth-gate.ts`.

## 3. Чем доказано

Файл: `server/__tests__/require-active-subscription.test.ts`, **28 тестов**.

Каждый негативный тест проверяет не код ответа, а что `handler` **не вызван ни
разу**: 503 после отработавшего handler'а означал бы, что побочный эффект уже
случился.

Red-before (снятие только своих файлов, `git stash push -- <path>` и точечные
временные патчи):

| Что снимаем | Красных из 28 |
|---|---|
| весь фикс middleware | **14** |
| общий allowlist `isPublicApiPath` | **1** |
| возврат `catch { next() }` | **9** |
| проверка формы ответа Directus | **1** |

**Отдельно к п. «проверка формы».** Первая версия этого теста
(`{ data: null }`) не стерегла ничего: при снятом guard'е обращение к полю у
`undefined` бросает TypeError, его ловит внешний catch, и ответ всё равно 503 —
тест зеленел по другой причине, а снятие guard'а не красило ни одного теста.
Заменено на тело-примитив `{ data: { data: 'unexpected-body' } }`: оно
разбирается без исключения, поэтому без guard'а читается как «бессрочная
подписка» и mutation проходит. Это и есть проверяемый fail-open.

## 5. Что НЕ сделано

- **`POST /api/tiktok/webhook` в allowlist не вносился.** Дефект шире гейта:
  `tiktokAuthRouter` не смонтирован в `server/index.ts` (наружу извлечён только
  GET OAuth callback), поэтому оба webhook-handler'а и client-вызовы
  `auth/start`, `accounts`, `sync-settings`, disconnect недостижимы; POST
  webhook при этом не проверяет подпись и echo'ит payload, открывать его
  allowlist'ом небезопасно. Заведено как **AI-49** под эпиком AI-44.
- **Живой простой Directus на проде не воспроизводился** — боевой Directus
  намеренно не останавливаем. Ветка 503 доказана только тестами.
- **Клиент не обучен новым кодам.** `SUBSCRIPTION_IDENTITY_REQUIRED` /
  `SUBSCRIPTION_SESSION_INVALID` / 503 фронт сейчас не различает — отдельная
  работа, в scope AI-39 не входила.
- **Третье перечисление публичного** (`registerPublicOAuthBypass`) не
  трогалось: §6 в части «единый allowlist» закрыт только для гейта подписки.
- **TTL 60 s не пересматривался.** Это буфер, на котором держится терпимость к
  простою Directus для платящих; менять — продуктовое решение.
- **Образ собирал не я.** Параллельно на проде работала вторая сессия (Claude
  Desktop, задачи SM); она подтянула `/root/smm-build-clean` на `81093b3d2` и
  собрала образ уже с этим фиксом. Свою `docker compose build smm` из
  `/root/smm` я прервал: docker берёт контекст из рабочего дерева, и в образ
  уехали бы чужие незакоммиченные `hermes_dashboard/`, `silentsentry_api/`,
  `smmniap_static/silentsentry/`. Проверял результат постфактум — см. п. 4.
