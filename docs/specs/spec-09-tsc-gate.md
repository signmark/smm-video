# Spec §9 — Полный TypeScript check как deploy gate

**Effort:** high (итеративно) · **Исполнитель:** Hermes · **Ревью:** Mavis (пачками)

## Цель

`tsc --noEmit` по всему проекту = 0 ошибок и обязательный gate в CI. Сейчас ~399 ошибок в 80 файлах (замер 2026-07-23; пересчитать первым шагом!).

## Стратегия (строго итеративно, НЕ один PR)

1. **Замер и классификация.** `npx tsc --noEmit -p tsconfig.json > tsc-baseline.txt`; сгруппировать по коду ошибки (TS2339, TS2345, ...) и по файлу. Runtime-significant первыми: обращения к несуществующим полям, неверные аргументы. Отчёт — в `docs/followups/tsc-baseline-<дата>.md`.
2. **Разделить конфиги.** `tsconfig.server.json` + `tsconfig.client.json` (разные lib/jsx), оба наследуют базу. `tsconfig.critical.json` не трогать до конца работ (он — действующий gate).
3. **Ratchet-механизм.** Скрипт `scripts/tsc-ratchet.mjs`: хранит число ошибок (`tsc-error-budget.json`), CI падает если ошибок стало БОЛЬШЕ, чем в бюджете; уменьшение — автообновление бюджета в том же PR. Так каждый PR может только улучшать.
4. **Пачки фиксов:** по подсистемам (соответствие memory-урокам!), максимум ~30 ошибок на PR, полный vitest после каждой пачки. Приоритет: server/api → server/services → client hooks → client components.
5. Финал: budget=0 → заменить ratchet на прямой `tsc --noEmit` в CI (spec-07 workflow) как обязательный шаг; `tsconfig.critical.json` — удалить или оставить как fast-check.

## Тесты

Сам tsc — тест. Дополнительно: после каждой пачки полный vitest (фиксы типов любят менять поведение — «а тут вообще мёртвый код был»).

## Acceptance (на каждую пачку)

- [ ] Число ошибок в budget уменьшилось, vitest зелёный
- [ ] Ни одного `as any` / `@ts-ignore` как «фикс» без комментария-обоснования (ревьюер считает их)
- [ ] Runtime-significant исправления перечислены в handoff отдельно (кандидаты на реальные баги)

## Грабли

- Ошибки в мёртвом коде — повод удалить код (отдельным коммитом), не типизировать труп.
- Directus-типы: поля из schema drift (memory!) могут «типизироваться» неправильно — сверять с реальной схемой.
- Не трогать `_archive/` — исключить из tsconfig include.
